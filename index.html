Key MariaDB tuning parameters

innodb_buffer_pool_size — the most impactful parameter
Controls how much RAM InnoDB uses for caching data and index pages. Default is 128MB — severely undersized for production. Set to 70-80% of available RAM on a dedicated database server. For a 16GB server: innodb_buffer_pool_size = 12G. For a shared server (with app): 40-50% of RAM. This single change is responsible for the largest performance improvements in most MariaDB installations. Check current hit rate: SHOW STATUS LIKE 'Innodb_buffer_pool_read%';

max_connections — avoid the "Too many connections" error
Default is 151. Most web applications need 200-500. Each connection uses ~1MB RAM. Formula: set max_connections × 1MB must fit in available RAM after buffer pool. For high-traffic apps: use connection pooling (ProxySQL, MaxScale) instead of raising max_connections — pooling 1000 app connections into 100 DB connections is far more efficient. Always set max_connections to 20% more than your expected peak.

innodb_log_file_size — critical for write-heavy workloads
Default is 96MB. For write-heavy applications, this is too small — causes frequent log flushes and write stalls. Set to 256MB-1GB for mixed workloads, 1-2GB for heavy OLTP. After changing: stop MariaDB, delete old ib_logfile0 and ib_logfile1, restart. Check write throughput with: SHOW ENGINE INNODB STATUS\G and look for "Log sequence number" growth rate.

FAQ — MariaDB performance tuning tools
Free tools: Percona PMM (best full monitoring), MySQLTuner (quick config audit), MariaDB Performance Schema (built-in query analysis), Slow Query Log (built-in), Netdata (real-time), Prometheus + mysqld_exporter (Grafana dashboards). Paid: SolarWinds DPA (enterprise), Releem (AI auto-tuning, free for 1 server). Start with: MySQLTuner for a quick audit, then Percona PMM for ongoing monitoring.
innodb_buffer_pool_size is the single most impactful setting. Default 128MB is severely undersized — set to 70-80% of RAM on a dedicated server. For a 16GB server: 12G. Second most important: innodb_log_file_size (256M-1G for write workloads), max_connections (set to peak + 20%), and innodb_io_capacity (set to 200 for HDD, 2000 for SSD). Use the tuner above to calculate all values for your server.
Three methods: (1) Slow Query Log — add to my.cnf: slow_query_log=1, slow_query_log_file=/var/log/mysql/slow.log, long_query_time=1. Analyze with: mysqldumpslow -s t /var/log/mysql/slow.log. (2) Performance Schema — query: SELECT * FROM performance_schema.events_statements_summary_by_digest ORDER BY SUM_TIMER_WAIT DESC LIMIT 10;. (3) Percona PMM — Query Analytics shows top slow queries with EXPLAIN automatically.
MySQLTuner is a Perl script that analyzes your running MariaDB instance and gives configuration recommendations. Install: wget http://mysqltuner.pl/ -O mysqltuner.pl. Run: perl mysqltuner.pl --user root --pass yourpassword. Important: run after at least 24 hours of production traffic — recommendations based on startup stats are inaccurate. It will show buffer pool hit rate, key buffer usage, connection utilization, and specific my.cnf changes to make.
